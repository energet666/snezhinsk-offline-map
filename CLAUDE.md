# map-offline — заметки для Claude

Офлайн-карта Снежинска (Челябинская область) на Leaflet, данные — GeoJSON из OSM (через Overpass API).

## Конвенции

- Локальный dev-сервер всегда запускать на порту 5173 (`./run.sh` использует 5173 по умолчанию).
- `TODO.txt` — личный рабочий список пользователя, в CP1251. Читать через `iconv -f CP1251 -t UTF-8 TODO.txt`. Не коммитить изменения в этот файл — это черновик пользователя, не часть репозитория по сути (хотя физически лежит в директории).

- №3 — полигон двора оказывался поверх домов при переключении Карта→Спутник→Карта. Причина: Leaflet SVG-рендерер при повторном добавлении слоя дописывает его paths в конец общего `<svg>`, поверх зданий. Исправлено через `map.createPane('landusePane')` с `zIndex: 350`, применённый ко всем базовым векторным слоям (landuse/water/railway/roads) в `app.js`.
- Бонус — коллизия цветов landuse: многие типы landuse не имели цвета и совпадали с цветом зданий. Расширена `LANDUSE_COLORS` в `style.js`.

**Сделано (2 сессия)**:
- №9 — центр номера дома: `polygonCentroid()` в `app.js` теперь считает настоящий взвешенный по площади центроид (формула шнурования), а не среднее вершин кольца. Для вогнутых зданий (L-образных), где такой центроид всё равно попадает мимо контура, есть фолбэк `poleOfInaccessibility()` — grid-search точки, максимально удалённой от границ. Проверено на здании Комсомольская 6 (39 вершин): старый центр был вне контура, новый — внутри.
- №6 — повтор названий улиц: OSM режет одну улицу на много коротких way (по кварталам/перекрёсткам), и `addStreetLabels()` раньше расставляла подписи независимо на каждом — из-за этого имя повторялось намного чаще, чем задумано `STREET_LABEL_STEP_PX`. Теперь подписи группируются по имени улицы, и используется единый список уже расставленных позиций (в пикселях) на всю улицу, а не на один сегмент.
- №5 — объекты пропадали при приближении: **не баг в коде**, а зона покрытия спутниковых тайлов (`tiles/`) сужалась на высоких зумах (на z13 покрыт весь город, на z17 — заметно меньшая область в центре). Докачано ~2500 недостающих тайлов z14–17 с Esri (`http://server.arcgisonline.com/.../MapServer/tile/{z}/{y}/{x}`, plain HTTP — see ниже про Overpass) скриптом в scratchpad — теперь покрытие одинаковое на всех зумах 12–17.
- №10 — гаражи: 254 отдельных здания (`building=garage(s)`) уже были в `data/buildings.geojson`, но рендерились как обычные дома (тот же бежевый). Добавлен отдельный стиль (сиреневый, в цвет `landuse=garages`) и попап «Гараж» при клике на здание без имени/адреса.
- №8 — названия админ. зданий: добавлен `adminBuildingLabel()` в `style.js` (маппинг `building`/`amenity` → русское название: Школа, Детский сад, Поликлиника, Дом культуры, Дом прощаний и т.д.), подписи показываются с zoom 15 как отдельный `kind: 'admin'` в `labelPoints`. Используется `p.name`, если есть в OSM, иначе общий тип. Работает и для POI без здания (см. школа 135 в №1).
- №7 — гибридный режим спутника: дороги (`roadsCasing`/`roadsCenter`) вынесены из `mapLayerGroup` (это base layer, скрывается целиком при переключении на Спутник) в отдельный `roadsGroup`, добавленный на карту напрямую — теперь всегда видны, включая режим Спутник. Здания в спутнике уже были невидимы (`buildingStyle()`), landuse/water/railway остаются скрыты вместе с `mapLayerGroup`. `labelsGroup` (подписи домов/улиц/админ.) и так был overlay, показывался в обоих режимах.
- №1 (частично) — школа 135: подтверждено через Overpass, что в OSM для неё вообще нет полигона здания (только точка `amenity=school`, `name=Школа 135`). Добавлен второй проход в `buildLabelIndex()`: POI с админ-типом (см. №8), не попавшие ни в одно здание через `buildOrgIndex` (теперь также возвращает `matchedPoiIds`), тоже получают подпись на карте. Школа 135 теперь видна.

**Важно про Overpass API**: HTTPS до `overpass-api.de`/зеркал не проходит из этого окружения (TLS/сеть блокируется), но **plain HTTP работает** (`http://overpass-api.de/api/interpreter`). Также area-запросы (`area["name"="Снежинск"]...`) часто выдают "server too busy" — используйте `[bbox:56.0229,60.6445,56.1211,60.8203]` в заголовке запроса вместо `area`, это стабильно быстрее.
