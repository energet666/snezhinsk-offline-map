# Оффлайн-карта Снежинска

Полностью автономное веб-приложение с картой Снежинска (Челябинская область):
- режим **«Карта»** — улицы, дома с номерами, здания (данные OpenStreetMap)
- режим **«Спутник»** — снимки Esri World Imagery
- слой **«Названия и объекты»** (улицы, номера домов) можно включить поверх спутника (как гибридный режим Google Maps)
- **организации** не загромождают карту подписями — появляются в попапе по клику на здание
- слой **«Парковки»** — отдельный чекбокс, площадки и точки парковок
- поиск по улицам, номерам домов, организациям (включая те, что не попали в контур здания) и населённым пунктам
- **смежные населённые пункты** — кроме самого Снежинска на карте есть соседние сёла (Воздвиженка, Воскресенское); их названия подписаны на малых зумах

Всё работает без интернета после первого запуска — данные и тайлы уже скачаны и лежат локально.

## Запуск

```bash
cd /root/playground/map-offline
python3 server.py
```

Откройте http://localhost:8765 в браузере.

Сервер — обычный `http.server`, интернет ему не нужен: все ресурсы (Leaflet, GeoJSON-данные, тайлы) уже находятся в этой папке.

## Структура

- `data/*.geojson` — улицы, здания (с номерами домов), парковки, водоёмы, зелень, ж/д — выгружены из OpenStreetMap (Overpass API) в границах Снежинска. Организация попадает в попап здания, если её точка лежит внутри контура этого здания (point-in-polygon); иначе она доступна только через поиск.
- `data/poi.geojson` — организации. Начиная с 4 сессии генерируется из `newData_140826/02_FINAL_2gis_organizations.json` скриптом `scripts/convert_2gis_poi.py` (см. «Ограничения» ниже), не из OSM.
- `data/memorials.geojson` — памятники, скульптуры и мемориальные доски (слой «Памятники»). Собирается скриптом `scripts/build_memorials.py` из двух источников сразу: OSM (`historic=memorial|monument`, `tourism=artwork` через Overpass) и категорий «Памятники и скульптуры»/«Памятные доски» из того же 2GIS-файла — по отдельности ни один источник не полон (памятник Ленину, Вечный огонь, Бажов есть только в OSM; воины-пограничники, «Спираль вечности» и почти все доски — только в 2GIS). Совпадающие объекты сливаются в одну запись.
- `data/places.geojson` — населённые пункты (`place=village|town|…`): из них берутся подписи сёл на карте и записи в поиске.
- `tiles/{z}/{x}/{y}.png` — растровые спутниковые тайлы Esri World Imagery, зумы 10–17 (~7100 тайлов, 105 МБ). Город покрыт одинаково на всех зумах 12–17; сёла — тоже на 12–17, а прямоугольник между городом и сёлами залит на 12–15, чтобы при панорамировании подложка не обрывалась. Докачивается `scripts/fetch_tiles.py`.
- `scripts/fetch_osm_area.py` — выгрузка `data/*.geojson` из Overpass по списку областей (`AREAS`: город и каждое село отдельным bbox). Слияние аддитивное: фича с уже существующим OSM id не перезаписывается, поэтому ручные правки (адреса зданий по 2GIS, имена стадионов) переживают повторный запуск. Умеет `relation[type=multipolygon]` — старый экспорт их терял целиком, из-за чего в данных не было, например, здания школы 135.
- `lib/` — локальная копия Leaflet 1.9.4 (карта не зависит от внешних CDN).
- `index.html`, `style.css` и `src/*.js` — само приложение. Код разбит на ES-модули (точка входа — `src/main.js`, подключается одним `<script type="module">`), сборщик не используется:
  - `main.js` — загрузка данных и проводка контролов/событий;
  - `map.js` — сам объект Leaflet-карты; `config.js` — все пороги/константы; `storage.js` — что запоминается в localStorage;
  - `geo.js` — геометрия (point-in-polygon, центроид), `orgindex.js` — привязка организаций к зданиям;
  - `layers.js` — базовые слои и парковки, `labels.js` — подписи, `memorials.js` — памятники, `search.js` — поиск;
  - `tagstyles.js` — таблицы «тег OSM / категория 2GIS → цвет и русское название», `popups.js` — HTML попапов.
  Из-за ES-модулей страницу нужно открывать через локальный сервер (`./run.sh`), а не двойным кликом по `index.html` (`file://` браузер заблокирует по CORS).
- `server.py` — локальный сервер на стандартной библиотеке Python.

## Ограничения и что можно улучшить

- **Покрытие данных** — сам Снежинск с буфером ~2–4 км за границей застройки плюс отдельные bbox'ы соседних сёл. Область целиком не покрыта: между городом и сёлами векторных данных нет (там садовые массивы), только спутниковая подложка на малых зумах.
- **Дороги сёл пока не выгружены.** У Воздвиженки и Воскресенского есть дома, зелень и вода, но нет улиц: выгрузка слоя `roads` не прошла — Overpass отвечал 502. Лечится повторным запуском `python3 scripts/fetch_osm_area.py --areas vozdvizhenka,voskresenskoe --layers roads`, данные допишутся к существующим.
- **Ближний Береговой и Знаменка не добавлены** по той же причине. Команда для них: `python3 scripts/fetch_osm_area.py --areas blizhniy_beregovoy,znamenka` (тайлы для них уже скачаны).
- **Источник организаций — ручной сбор с 2GIS, не OSM.** Автоматическая интеграция через API 2GIS не использовалась (лицензия law.2gis.ru/licensing-agreement, п. 5.1.2/5.1.4/5.1.8, прямо запрещает извлекать данные из их баз и строить на них свои сервисы) — но `newData_140826/02_FINAL_2gis_organizations.json` собран владельцем проекта вручную для личного некоммерческого использования, не через автоматизированное извлечение под этой лицензией. 611 организаций (из 617 собранных — 6 без координат пропущены при конвертации).
- **Телефон/часы работы/сайт** показываются в попапе здания там, где это есть в исходных данных: из 611 организаций телефон указан у 371, часы работы — у 490, сайт — у 379 — заметно полнее, чем было с OSM (96/133/104 из 690).
- **Названия улиц** в OSM указаны не для всех проездов (170 из 1609 линий дорог имеют name) — это ограничение исходных данных OSM для Снежинска, а не приложения.
- **Спутник**: максимальный явно скачанный зум — 17 (~0.6–1 м/пиксель на этой широте), при увеличении дальше Leaflet будет растягивать эти же тайлы (`maxNativeZoom`). Если нужна более высокая детализация — можно перезапустить `download_tiles.py` (в истории сессии) с `MAX_Z=18` для более точной зоны.
- **Спутник — источник данных**: Esri World Imagery, лицензия допускает офлайн-использование в некоммерческих целях. Прямое массовое скачивание тайлов Google Maps для офлайна нарушает условия использования Google, поэтому не использовалось.
- Для актуализации домов/улиц — `python3 scripts/fetch_osm_area.py --areas all` (добавит новое, ручные правки не тронет) или с `--replace` для честного пересбора с нуля. Для актуализации организаций — обновить `newData_140826/02_FINAL_2gis_organizations.json` и перезапустить `scripts/convert_2gis_poi.py`, а следом `scripts/build_memorials.py` (он берёт памятники из того же файла плюс из Overpass).
